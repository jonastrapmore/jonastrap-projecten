Het project

Dit dashboard is een persoonlijk project: een single-page webapplicatie die vier dagelijkse noden samenbrengt op één centrale pagina. De vier widgets tonen het actuele weerbericht voor opgeslagen locaties, een dagelijks avondmaalrecept met filters voor dieet en bereidingstijd, de NASA-foto van de dag met uitleg, en een eenvoudig takenbeheer.

Het project dient als demonstratiestuk van mijn vaardigheden in webontwikkeling en API-integratie. De nadruk lag bewust op een nette, professionele uitwerking die de geleerde concepten concreet toepast: een duidelijke architectuur, type-veiligheid, integratie met externe API's en degelijke foutafhandeling.

Technische keuzes

  • Build tool: Vite, voor een snelle ontwikkelomgeving met native TypeScript-ondersteuning.
  • Taal: TypeScript, voor type-veiligheid en betere onderhoudbaarheid.
  • CSS-framework: Bootstrap 5, voor een degelijke grid en ingebouwde dark mode.
  • API's: OpenWeatherMap (weer), Spoonacular (recepten), NASA APOD (foto van de dag), en een vertaal-API voor de Nederlandse inhoud.

De oplossing documenteren

Ik koppel dit project aan dit doel omdat ik de oplossing volledig heb gedocumenteerd in een uitgebreide README, aangevuld met commentaar in de code zelf. Zelfreflectie

Wat ging goed

De README groeide mee met het project: bij elke afgewerkte widget vulde ik de voortgangstabel, de functionaliteiten en de planning aan. Daardoor bleef de documentatie actueel en kon ik op elk moment tonen wat af was en wat het deed.

Wat ik geleerd heb

Ik leerde dat documentatie meer is dan een handleiding achteraf. Door de doelen en de scope vooraf vast te leggen, hield ik zelf overzicht over wat er nog moest gebeuren. Goede documentatie stuurt dus ook de ontwikkeling, niet alleen het gebruik.

Uitdagingen

De grootste uitdaging was de juiste hoeveelheid detail kiezen: genoeg om de scope en functionaliteiten duidelijk vast te leggen, zonder de README onleesbaar te maken. Ik loste dit op met een vaste structuur per widget (functionaliteit en technische aanpak gescheiden) en samenvattende tabellen.

Wat beter kan

  • Screenshots opnemen in de README zelf, zodat ook visueel duidelijk is hoe elke widget eruitziet.
  • Documentatie van de code uitbreiden met korte beschrijvingen per functie in een vaste stijl (bijvoorbeeld JSDoc).

Conclusie

Dit project toont de twee kernpunten van het doel aan: ik documenteer de doelen van de ontwikkeling via de doelstelling en de gefaseerde planning, en ik leg de scope en functionaliteiten vast via een beschrijving per widget, een API-overzicht en een voortgangstabel, aangevuld met commentaar in de code zelf.
